## Curated Question Set

1. How do you decide whether an endpoint should use `GET`, `POST`, `PUT`, `PATCH`, or `DELETE`?
2. What makes an API feel predictable for its clients?
3. How would you choose between `200`, `201`, `204`, `400`, `404`, and `409` in common backend scenarios?
4. What does idempotency mean, and why does it matter for backend services?
5. How should validation errors be represented in an API?
6. What are the signs that a controller is doing too much work?
7. How would you design an endpoint that depends on a slow downstream service?

## Follow-up Prompts

- What retry behavior do you expect from clients?
- What state transition is this endpoint actually performing?
- Which failure modes should the API make explicit?
