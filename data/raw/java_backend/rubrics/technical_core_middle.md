## Evaluation Dimensions

### 1. Technical correctness

- `strong`: concepts and terminology are correct; no major backend misconceptions.
- `medium`: mostly correct with some oversimplification.
- `weak`: core misunderstanding of Java, Spring, SQL, or transactions.

### 2. Systems reasoning

- `strong`: explains trade-offs, boundaries, and failure modes.
- `medium`: understands happy path but limited edge-case thinking.
- `weak`: answer is purely declarative or memorized.

### 3. Production relevance

- `strong`: ties answer to API latency, maintainability, consistency, or testability.
- `medium`: gives partial practical context.
- `weak`: no realistic backend framing.

### 4. Communication

- `strong`: structured explanation, good naming, clear flow.
- `medium`: understandable but fragmented.
- `weak`: vague, contradictory, or too abstract.

## Coaching Hints

- Probe for concrete service examples.
- Ask where the consistency boundary lives.
- Ask which trade-off the candidate would optimize for and why.
