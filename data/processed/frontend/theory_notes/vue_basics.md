## Краткое резюме

Vue строит интерфейс из компонентов, которые обмениваются данными через `props` и события, а реактивность синхронизирует состояние с отображением. Для повседневной разработки важнее всего границы ответственности компонента, `computed`, `watch`, `ref`, `reactive`, slots и composables.

## Ключевые идеи

1. Границы компонента:
   компоненту нужна чёткая UI-ответственность.
2. Поток данных:
   `props` приходят сверху, события сообщают о действиях наружу.
3. Реактивность:
   `ref` удобен для отдельных значений, `reactive` — для объектного состояния.
4. Вычисляемые значения:
   `computed` лучше подходит для производных данных, чем ручной пересчёт в шаблоне.
5. Побочные эффекты:
   `watch` полезен, когда нужно реагировать на изменение данных, но он не должен заменять всё подряд.
6. Переиспользование:
   slots формируют API компонента, composables помогают делить логику без тяжёлой глобальной абстракции.

## Что важно для интервью

- Объяснять не только API, но и зачем нужен такой раздел ответственности.
- Уметь сравнить `computed` и `watch` на реальном UI-сценарии.
- Приводить пример, где неправильное владение state или слишком большой компонент приводит к багам.
